# Framework Overview

Source: Scytale SDR Hub → SDR Resource → [Framework Overview](https://app.notion.com/p/scytaleai/Framework-Overview-32839e8f942080d8a77bd0fcd98b0b6d) (Notion, confidential — for sales use only). Pulled 2026-09-14 for use as the reference behind `backend/src/util/applicableFrameworks.js`, which suggests frameworks likely applicable to a prospect. Re-pull and update this file (and the rules that use it) if the Notion catalog changes.

- **Full Framework** — a standalone, independent framework that can be sold on its own.
- **Half Framework** — an extension or add-on that must be sold alongside a primary framework (not suggested on its own by the rule engine).
- **Custom Framework** — tailored to specific enterprise or partner requirements; escalate internally for guidance.

## Full Frameworks

| Framework | Description |
|---|---|
| SOC 1 | Assurance over internal controls relevant to financial reporting, for service organizations that impact their clients' financials. |
| SOC 2 | Trust-based audit of security, availability, confidentiality, processing integrity, and privacy controls — the go-to for SaaS companies. |
| ISO 27001 | The international gold standard for building and maintaining an Information Security Management System (ISMS). |
| ISO 42001 | The world's first international standard for AI management systems — ensures responsible development and deployment of AI. |
| ISO 9001 | The globally recognized standard for Quality Management Systems (QMS), demonstrating consistent delivery of quality products and services. |
| ISO 22301 | International standard for Business Continuity Management Systems (BCMS) — ensures organizations can operate through disruptions. |
| ISO 13485 | International standard for Quality Management Systems (QMS) specific to the medical device industry. |
| HIPAA | U.S. federal law protecting the privacy and security of patients' health information (PHI) for healthcare organizations and their partners. |
| PCI DSS | Security standard mandated by major card brands to protect cardholder data and secure payment processing environments. |
| GDPR | EU regulation governing how organizations collect, store, and process personal data of EU residents. |
| SOX ITGC | IT General Controls required under the Sarbanes-Oxley Act — ensures the integrity of financial reporting systems for public companies. |
| CCPA | California's landmark privacy law giving consumers rights over their personal data and placing obligations on businesses that handle it. |
| CMMC | U.S. Department of Defense framework requiring defense contractors to meet specific cybersecurity standards. Level 1 available; Level 2 on request. |
| Cyber Essentials | UK government-backed scheme verifying defenses against common cyber threats (audited version: Cyber Essentials PLUS). |
| Essential 8 | Australia's top 8 cybersecurity mitigation strategies (Australian Signals Directorate baseline). |
| CSA STAR | Cloud Security Alliance registry validating cloud providers' security posture (self-assessment Level 1, or third-party audit Level 2). |
| Bill 64 / Law 25 | Quebec's private-sector privacy legislation modernizing handling of personal information of Quebec residents. |
| POPI Act | South Africa's Protection of Personal Information Act. |
| NIST 800-53 | Catalogue of security/privacy controls for U.S. federal information systems (currently Low Baseline; Med/High on request). |
| NIST CSF 2.0 | Voluntary U.S. cybersecurity framework for managing and reducing cyber risk, now expanded for all sectors. |
| NIS2 Directive | EU directive setting baseline cybersecurity requirements for essential/important entities in critical sectors. |
| EU AI Act | EU regulation establishing risk-based requirements for AI systems. |
| DORA | EU regulation requiring financial entities to ensure digital operational resilience (ICT risk management, third parties). |
| TISAX | Automotive industry information security standard (based on ISO 27001), required by OEMs/suppliers. |
| CIS Critical Security Controls | Prioritized best-practice cybersecurity actions (currently IG1; IG2/IG3 on request). |
| PPL (Protection of Privacy Law) | Israel's privacy legislation (Amendment 13). |
| COPPA | U.S. federal law protecting the online privacy of children under 13. |
| GovRAMP | State/local government cloud-service authorization framework, modeled on FedRAMP. |
| C5 | German BSI cloud security attestation standard — mandatory baseline for cloud security in Germany, esp. regulated industries/government. |

## Half Frameworks (extensions — sold alongside a Full Framework, never suggested alone)

| Framework | Extends | Description |
|---|---|---|
| ISO 27017 | ISO 27001 | Additional security controls for cloud service providers and customers. |
| ISO 27018 | ISO 27001 | Protecting Personally Identifiable Information (PII) in public cloud environments. |
| ISO 27701 | ISO 27001 | Adds a Privacy Information Management System (PIMS) — helps with GDPR and other privacy regs. |
| ISO 27799 | ISO 27001 | Tailored for healthcare — guidance on protecting personal health information. |
| ISO 27032 | ISO 27001 | Cybersecurity guidelines for improving the state of security in cyberspace. |
